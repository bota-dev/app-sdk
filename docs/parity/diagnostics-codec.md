# Shared Diagnostics Codec and Typed C ABI

## Scope and Authority

The Rust codec matches the valid diagnostic report and command formats in
maintenance SDK revision `318974f925a573cf04b0d624978bee04784af09b`
(`src/ble/deviceDiagnostics.ts`, `constants.ts`, and the diagnostics tests).
It owns deterministic wire decoding and command encoding only. It does not
subscribe, write to a device, acknowledge an event automatically, call a backend,
or carry recording/audio bytes. Native hosts own read lifetime and BLE transport.

Canonical wire constants and detail offsets are in
[`device-protocol.yaml`](../../protocol/manifest/device-protocol.yaml), with Rust
output generated by `cargo xtask protocol generate`. Existing ABI v1 meanings,
function signatures, struct layouts, and field IDs 1 through 170 are unchanged.

## Wire Format

Use service `B07A0007-0000-1000-8000-00805F9B34FB`, control characteristic
`B07A0007-0001-1000-8000-00805F9B34FB`, and notification characteristic
`B07A0007-0002-1000-8000-00805F9B34FB`. All multibyte integers are little-endian.

| Message | Layout |
| --- | --- |
| LIST `0x10` | One command byte |
| ACK `0x11` | Command byte, event ID u64 |
| META `0x90` | 17 bytes: opcode, index u8, event type u8, reason u16, uptime u32, event ID u64 |
| SIGNATURE `0x91` | 10 bytes: opcode, index u8, signature u64 |
| END `0x92` | Two bytes: opcode, event count u8 |
| DETAIL `0x95` | Opcode, index u8, offset u16, total u16 (=176), 1-14 payload bytes |

The complete detail is exactly 176 bytes, version 1. It includes a canonical
12-character lowercase hex build ID, subsystem and prior state, optional fault
registers, normalized execution addresses and task, optional heap/stack values,
and up to eight signed breadcrumbs. PC and breadcrumb counts are clamped to six
and eight, respectively, matching the reference. Zero addresses are omitted;
nonzero addresses use `rom:`, `ram:`, or `sdram:` plus eight lowercase hex digits.
Register strings have eight lowercase hex digits. Event IDs and signatures have
16 lowercase hex digits, preserving all u64 bits without floating-point loss.

Known reason, subsystem, state, and breadcrumb values use the reference names.
Unknown values fall back to `unknown_cpu_exception`, `system`, `unknown`, and
`state_changed`, respectively. Runtime mask bits independently control heap and
stack presence; zero is a present value when its bit is set. Absent reports,
runtime values, task names, and return addresses remain absent, not synthetic zeros.

## Core API

Exported from `bota_device_sdk_core::protocol`:

```rust
DeviceDiagnosticsDecoder::default()
DeviceDiagnosticsDecoder::push(&mut self, packet: &[u8])
    -> Result<Option<DeviceDiagnosticsBatch>, DeviceSdkError>
DeviceDiagnosticsDecoder::reset(&mut self)
encode_diagnostic_command(command: DiagnosticCommand<'_>)
    -> Result<Vec<u8>, DeviceSdkError>
```

Commands are `DiagnosticCommand::List` and
`DiagnosticCommand::Acknowledge(&str)`. ACK accepts only exactly 16 lowercase ASCII
hex characters; no uppercase, padding, prefixes, whitespace, or truncation.
For example, `0123456789abcdef` encodes to `11 ef cd ab 89 67 45 23 01`.
The typed batch contains `DeviceDiagnosticEvent`, optional `DiagnosticReport`,
`DiagnosticFault`, `DiagnosticExecution`, optional `DiagnosticRuntime`, and
`DiagnosticBreadcrumb` values. Serde derives support ordinary core model use;
the C ABI never serializes or transports these values as JSON.

## C Entry Points

The existing entry points are used without signature changes:

```c
BotaDeviceSdkStatusV1 bota_device_sdk_v1_protocol_decode(
    BotaDeviceSdkEngineV1 *engine,
    const BotaDeviceSdkPacketViewV1 *packet,
    BotaDeviceSdkPacketV1 **out_packet);
BotaDeviceSdkStatusV1 bota_device_sdk_v1_protocol_encode(
    BotaDeviceSdkEngineV1 *engine,
    const BotaDeviceSdkPacketViewV1 *packet,
    BotaDeviceSdkPacketV1 **out_packet);
```

Use `abi_version=1`, zero operation/reserved/request/cancellation metadata,
and the existing typed field representation. A successful output is an owned
packet: inspect with `bota_device_sdk_v1_packet_view`, copy values as needed,
then call `bota_device_sdk_v1_packet_free` exactly once. Input storage is borrowed
only during the call. Output storage remains valid independently of subsequent
engine calls until that packet is freed.

### Decode: `0x0525`

`BOTA_DEVICE_SDK_V1_PROTOCOL_DECODE_DIAGNOSTICS` accepts exactly one field:
existing `VALUE` (ID 30, BYTES), containing one notification of at most 20 bytes.
An empty byte slice is the explicit reset operation and returns an empty packet.
Intermediate notifications also return an empty packet with `Ok` status.
Only END returns the complete typed batch, with output kind `0x0525`.

The following names have C prefix `BOTA_DEVICE_SDK_V1_FIELD_DIAGNOSTIC_` and Rust
prefix `field_id::DIAGNOSTIC_`. Types are the existing UNSIGNED (1), SIGNED (2),
BOOL (3), and UTF8 (4). All repeated fields retain their order.

| ID | Name | Type | Presence / meaning |
| --- | --- | --- | --- |
| 171 | SCHEMA_VERSION | UNSIGNED | Batch prefix, 1 |
| 172 | EVENT_COUNT | UNSIGNED | Batch prefix, number of complete events |
| 173 | EVENT_ID | UTF8 | Starts each event group; canonical 16-hex ID |
| 174 | EVENT_TYPE | UTF8 | Required event type name |
| 175 | REASON_CODE | UTF8 | Required reason name |
| 176 | UPTIME_MS | UNSIGNED | Required u32 value |
| 177 | SIGNATURE | UTF8 | Required canonical 16-hex signature |
| 178 | FIRMWARE_BUILD_ID | UTF8 | Required canonical 12-hex build ID |
| 179 | SUBSYSTEM | UTF8 | Required subsystem name |
| 180 | STATE_BEFORE_EVENT | UTF8 | Required state name |
| 181 | HAS_REPORT | BOOL | Required; false ends the event group |
| 182 | CPU_ID | UNSIGNED | Required when report exists |
| 183 | CPU_EMU | UTF8 | Required when report exists, eight hex digits |
| 184 | CORE_EMU | UTF8 | Required when report exists, eight hex digits |
| 185 | HSB_EMU | UTF8 | Required when report exists, eight hex digits |
| 186 | AUDIO_EMU | UTF8 | Required when report exists, eight hex digits |
| 187 | WIRELESS_EMU | UTF8 | Required when report exists, eight hex digits |
| 188 | TASK | UTF8 | Optional nonempty task |
| 189 | RETI | UTF8 | Optional normalized address |
| 190 | RETS | UTF8 | Optional normalized address |
| 191 | PC_TRACE_COUNT | UNSIGNED | Required with report; number of nonzero addresses |
| 192 | PC_TRACE | UTF8 | Repeated exactly PC_TRACE_COUNT times |
| 193 | HEAP_FREE_BYTES | UNSIGNED | Optional u32 value selected by runtime mask |
| 194 | TASK_STACK_REMAINING_BYTES | UNSIGNED | Optional u32 value selected by runtime mask |
| 195 | BREADCRUMB_COUNT | UNSIGNED | Required with report, 0-8 |
| 196 | DELTA_MS | SIGNED | Breadcrumb triple start, sign-extended i32 |
| 197 | BREADCRUMB_CODE | UTF8 | Breadcrumb triple middle, reference name |
| 198 | BREADCRUMB_ARG0 | SIGNED | Breadcrumb triple end, sign-extended i32 |

Batch fields precede events. Events are ordered by ascending contiguous wire
index, not packet arrival order. Each event's fields appear in the table order.
Breadcrumbs are interleaved triples `(196,197,198)`, repeated BREADCRUMB_COUNT
times. Do not flatten repeated fields into a dictionary keyed by ID. The 64-field
input validation limit does not constrain output batches. Empty END produces
only fields 171=1 and 172=0, unlike an intermediate/reset packet with zero fields.

### Encode: `0x0526`

`BOTA_DEVICE_SDK_V1_PROTOCOL_ENCODE_DIAGNOSTIC_COMMAND` accepts:

- LIST: existing `COMMAND` (97, UNSIGNED) = `0x10`, with no other fields.
- ACK: `COMMAND` (97, UNSIGNED) = `0x11`, plus `DIAGNOSTIC_EVENT_ID`
  (173, UTF8), validated as described above.

Output kind is `0x0526`, with exactly one `VALUE` (30, BYTES) field containing
the encoded command. Encoding does not write BLE or reset the decoder. Unknown
commands, additional fields, duplicate fields, and incorrect types fail closed.

## Read Lifetime and Failure Rules

There is one diagnostics assembler per engine, separate from log decoding and
workflow state. Engines cannot share partial events. Native code must serialize
one read per engine, quiesce callbacks from the old read, and decode empty VALUE
before each new LIST/read, and on cancellation, disconnect, or failed setup.
There is no wire read ID, so resetting alone cannot identify late notifications:
the native read owner must reject callbacks from the previous subscription.

Every malformed recognized diagnostics packet and every invalid diagnostics
field/envelope clears all pending events. No partial batch is published. Ordinary
failures return `OperationFailed`, null output, and the existing structured
engine error. Unsupported ABI versions return `UnsupportedAbi`, null output,
and clear diagnostics. Invalid pointers are outside the live-pointer contract.
END always consumes the pending read, whether complete or invalid.

The decoder bounds notification length before copying ABI bytes. Each u8 index
has at most one fixed 176-byte detail buffer: at most 256 buffers, or 45,056
detail bytes, plus bounded metadata. END's u8 count limits a completed batch to
255 events; an assembled extra index is rejected rather than silently dropped.

Intentional fail-closed hardening versus the permissive reference: malformed
recognized packet lengths, unknown event types, duplicate META, zero-progress
detail chunks, noncanonical build IDs, and extra/unmatched END entries reject
and reset. Duplicate/out-of-order detail, invalid total/version/build ID,
missing metadata/signature/detail, and incomplete END also reject and reset.
Unknown message opcodes of at most 20 bytes (including log, ACK-result `0x93`,
and capabilities `0x94`) are ignored. A signature before META is ignored.

## Verification

- `cargo test -p bota-device-sdk-core --test diagnostics`
- `cargo test -p bota-device-sdk-ffi --test diagnostics --test packet_contract`
- `cargo xtask protocol generate --check`
- `cargo test --workspace`

Focused tests cover the exact maintenance fixture, all 176 detail bytes,
optional report/runtime fields, signed breadcrumb extremes, address regions,
fragment and envelope failures, recovery/reset, typed repeated output,
engine isolation, canonical command encoding, and maximum assembly capacity.
These are software-only checks, not physical-device qualification.

Implementation validation passed: eight focused core tests, five focused FFI
tests, the additive packet/header allocation contract, the full Cargo workspace
suite, workspace Clippy with all targets/features and warnings denied, generated
constants freshness, owned-file formatting, and the checked-in header digest.
The first workspace run caught a forbidden token in a header comment; the
comment was corrected without changing declarations, and the full suite rerun
passed. Native facade packaging and hardware validation are separate gates.
