# Android Facade Release Evidence

Status: published. Automated facade evidence and physical-device acceptance
were accepted before release; the protected workflow completed public artifact
verification on Android API 26 and API 35.

## Reviewed Capability

- `android_device_sdk` is the reviewed manifest capability for the Android AAR.
- It represents the complete public facade and native-host behavior covered by
  the Android foundation, lifecycle, workflow, compatibility, consumer, and
  emulator suites.
- Rust-only compatibility entries are not Android publication evidence and are
  never copied into the Android artifact capability list.

## Package Contract

- Maven coordinate: `dev.bota:bota-android-sdk`
- Minimum Android API: 26
- Compile and test Android API: 36
- Native ABIs: `arm64-v8a`, `armeabi-v7a`, `x86`, and `x86_64`
- Native libraries per ABI: `libbota_android_jni.so` and
  `libbota_device_sdk_ffi.so`
- Compatibility surface: `dev.bota.sdk` plus the deprecated `com.bota.sdk`
  migration facade frozen from Android SDK revision
  `0f06d2a22c55e4976778520cce42230d23ca4226`

## Publication Evidence

`tools/android/package-release.sh --check` performs two clean AAR builds,
compares the complete AAR and native-library digests, creates only the unsigned
local Maven repository, and generates the SPDX 2.3 SBOM and native manifest.

`tools/android/test-publication-graphs.sh` separately proves that unsigned
builds expose no signing tasks, protected staging fails before output without
both in-memory secrets, and a password-protected ephemeral PGP key produces
the exact signed raw and normalized Central Portal inventories.

Non-publishing CI reconstructs the local Maven repository from the immutable
release directory and runs it on the exact API 26 x86 and API 35 x86_64 lanes.
Each lane covers JNI, fixtures, workflows, concrete storage and Keystore hosts,
all 39 applicable protocol decode fixtures and 24 applicable encode fixtures,
the frozen source and precompiled legacy consumers, and an unrelated Maven
consumer. Maven module dependencies must exactly match the reviewed policy and
the SPDX license declarations. These automated results do not replace the
supervised Bota Pin and Bota Note matrix. The release coordinator has accepted
that matrix for this candidate; the repository does not contain private device
logs or credentials. Maven Central deployment
`6c4384ae-fe6a-4ec4-b9b3-774e437f07f7` reached `PUBLISHED`; protected release
workflow run `33685720066` then byte-verified the public repository and passed
the unrelated API 26 and API 35 consumer jobs.
The precompiled consumer fixture contains only Bota's test bytecode, records the
pinned legacy revision and frozen API digest, and is checksum verified; no
legacy SDK binary or private-repository credential is part of CI.

The cold Linux dependency graph also verifies the Guava and Jackson parent
POMs plus JUnit and coroutines BOM metadata that warm developer caches may not
request. Their Maven Central SHA-256 values are pinned in Gradle verification
metadata.
