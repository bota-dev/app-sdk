# Android Facade Release Evidence

Status: reviewed for automated publication packaging; coordinated `1.1.0`
publication remains gated by the release workflow and version bump.

## Reviewed Capability

- `android_device_sdk` is the reviewed manifest capability for the Android AAR.
- It represents the complete public facade and native-host behavior covered by
  the Android foundation, lifecycle, workflow, compatibility, consumer, and
  emulator suites.
- Rust-only compatibility entries are not Android publication evidence and are
  never copied into the Android artifact capability list.

## Package Contract

- Maven coordinate: `dev.bota:bota-android-sdk`
- Minimum Android API: 26
- Compile and test Android API: 36
- Native ABIs: `arm64-v8a`, `armeabi-v7a`, `x86`, and `x86_64`
- Native libraries per ABI: `libbota_android_jni.so` and
  `libbota_device_sdk_ffi.so`
- Compatibility surface: `dev.bota.sdk` plus the deprecated `com.bota.sdk`
  migration facade frozen from Android SDK revision
  `0f06d2a22c55e4976778520cce42230d23ca4226`

## Publication Evidence

`tools/android/package-release.sh --check` performs two clean AAR builds,
compares the complete AAR and native-library digests, creates only the unsigned
local Maven repository, and generates the SPDX 2.3 SBOM and native manifest.

`tools/android/test-publication-graphs.sh` separately proves that unsigned
builds expose no signing tasks, protected staging fails before output without
both in-memory secrets, and a password-protected ephemeral PGP key produces
the exact signed raw and normalized Central Portal inventories.
