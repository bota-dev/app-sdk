# Beta.18 connected BLE MTU correction

The owner requested generated-JS migration and production Android testing of
Demo and Bota One. Beta.17 is public; this candidate corrects a physical Android
failure in its generic BLE PLX OS adapter under the original RN package name.

BLE PLX's Android `devices()` returns scan-cache entries without a valid MTU.
After successful connection, discovery and identity reads, beta.17 rejects that
entry with `invalid_mtu` and restarts discovery until Android throttles scans.
Source 4fa5f05 instead observes connected `requestMTUForDevice` results through
the existing captured transaction. It retains Rust retry bounds and physical
generation, peripheral identity and joined cancellation fences.

The new regression fails before the correction and passes after it. All 480
RN tests, strict source types, package builds, four private fixture tests and
23 focused BLE port cases pass. Demo's same installed Android host executes
the corrected JS adapter, reads the exact selected serial, paired state,
firmware 1.0.19, MTU 512, idle status and an empty catalog. No recording transfer,
cloud commitment or device cleanup is established by an empty catalog.

The phone test also identifies a stale initialized flag in both applications'
disconnect-listener hook. Their current-scope guard has a failing-before,
passing-after regression. Demo passes 13 runtime cases; One passes 19; both
strict app typechecks pass. One's separate production authentication rejects
the supplied test credential; authenticated One device testing remains pending.
Account/device mappings and credentials are excluded from committed evidence.
