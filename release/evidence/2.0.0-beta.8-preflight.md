# 2.0.0-beta.8 Android disconnection release candidate

The owner requested publication/adoption after pushing the fix directly to main.
Beta.8 carries Android confirmed-loss state invalidation and RN forwarding
without a status subscription. Flutter already uses the native connection stream.
No automatic reconnect, new public API, provisioning change or upload-fallback
authority is introduced. Public beta.7, historical tags and npm `latest` remain
unchanged during preparation.

## Physical evidence and limits

The tested native AAR came from CI 36629977148, artifact 11063110461, source
`9acff6511f5b1b64ecc4f00ec49bb188034861f2` (same tree as PR merge `e00865e`).
AAR SHA-256:
`265e4c82acd9db59603ddfab53501d816693fed428d546eeda677fcc08dd1275`.
The separate lab app saw events null, exact serial, null on phone Bluetooth-off,
exact serial after Bluetooth-on and explicit reconnect, then null on Disconnect.
Fresh status reported 100% battery, Idle and zero pending recordings. Bluetooth
was restored on and the lab app stopped. No wearable reset, rebind, recording,
deletion or firmware change was performed.

That artifact retained beta.7 metadata and is not the final beta.8 package.
Exact beta.8 example acceptance remains separate. Full candidate RN/Flutter UI,
physical iOS, out-of-range, background and other-device coverage are unverified.
The firmware compatibility matrix is unchanged; one 1.0.19 connection test does
not qualify every SDK workflow on that firmware.

Review basis: App SDK Architecture platform link events/native framework
ownership/presence invalidation; Connection Management unexpected loss;
repository release procedure exact-artifact promotion and one human approval.
The existing protected gate must be preserved. Source CI never establishes
publication, and publication never establishes untested physical behavior.
