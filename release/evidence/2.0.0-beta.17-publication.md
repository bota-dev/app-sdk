## Design review

The [runtime contract](../../docs/parity/react-native-runtime.md), following
App SDK Architecture §§5.5 and 6.3 and upload-management §1.1, keeps source
ownership, OS mechanics and delivery/physical gates separate.

| Requirement | Implementation and evidence | Status / remaining verification |
| --- | --- | --- |
| Preserve shared Rust ownership | Canonical executable JS, 136 differential RPCs and 715 actual pinned Hermes checks | Matched source/compiler/VM gates |
| Admit real production root routes without routing tricks | Rust empty-prefix admission, omitted `/v1` default, exact root/prefix and rejection fixtures in JS/native tests | Matched controlled source gates; production app/backend tests separate |
| Keep app imports native-free | Pure status/presence/version exports, actual public generated client and strict declarations | Matched public package consumer; installed OS ports separate |
| Preserve old pending native evidence | Generated Rust recognizes only the exact 12-byte successful-clear Android catalog; all other artifacts remain protected | Matched classifier; automatic pending-state migration not implemented |
| Preserve native compatibility | Frozen API/Codegen, nullable real BLE PLX contract without casts and full native CI/public consumers | Matched source/public native gates; app binary delivery separate |
| Preserve scope and client lifetime | Controlled A → B → A fresh-factory probe; idempotent app configuration required | Fresh-factory route matched; same-instance reconfiguration partial |
| Publish the original package and exact synchronized bytes | Main inventory, annotated tag, protected approval and all public archives/consumers | Matched across all five platforms |
| Preserve cloud commitment and separate durable device cleanup | Shared receiver/workflow tests and existing identity/receipt/cancellation fences | Matched source gates; installed durability and physical recovery unverified here |
| Deliver compatible logic through app OTA | Generated JS over installed version 1 OS ports | Package capability matched; app OTA and physical acceptance separate |

Tagged packaged documents retain their preparation snapshots. The complete
Flutter inventory remains immutable; this nonpackaged record supplies subsequent
publication evidence. Demo/Bota One app installation, authentication, wearable
admission, recording sync and app OTA evidence belong to their application review.
