## Findings

### P1 - Resolved: verification workflows became automatic during conflict resolution

The first merged candidate retained `push` and `pull_request` triggers in the
CI workflow instead of preserving `origin/main`'s manual-only verification
policy. That could have triggered repository automation merely by publishing a
branch or pull request. A parsed-YAML regression now requires exactly one
`workflow_dispatch` trigger for both verification workflows at
`tools/xtask/tests/release_readiness.rs:221`. The corrected trigger blocks are
at `.github/workflows/ci.yml:3` and `.github/workflows/license-gate.yml:3`.

RED:

```text

exit 101; 0 passed, 1 failed, 28 filtered out
assertion: CI trigger count was 3, expected 1
```

GREEN:

```text

exit 0; 1 passed, 0 failed, 28 filtered out
```

### P2 - Resolved: Flutter conformance overstated the integrated workflow set

The first post-merge package run discovered 33 canonical traces and failed five
tests because the pre-integration Flutter test assumed every canonical command
was in the Flutter beta. The four newly integrated Encrypted Upload v2 traces
belong to native and React Native in this release. The contract now discovers
all 33, asserts the explicit four-trace unsupported set at
`frameworks/flutter/bota_flutter_sdk/test/workflow_conformance_test.dart:196`,
and replays all 29 supported traces through the typed Dart facade.

RED:

```text
tools/flutter/package-release.sh --write-example
exit 1; 83 passed, 5 failed
failures: canonical count 29 versus 33 and four unsupported
transfer_encrypted_recording scenarios
```

GREEN:

```text
tools/flutter/run-flutter.sh test frameworks/flutter/bota_flutter_sdk/test/workflow_conformance_test.dart
exit 0; 30 passed, 0 failed
```

### P3 - Accepted: Flutter Apple bridge has Swift 6 sendability warnings

`tools/flutter/test-apple-adapter.sh` passes all 35 tests but Pigeon 28 output
and `BotaAppleAdapter.swift` emit sendability warnings under the installed
Swift 6 compiler. The supported plugin contract intentionally compiles this
generated bridge in Swift 5 language mode. The separately shipped native Apple
SDK passes strict concurrency with warnings as errors. Disposition: retain the
reviewed Pigeon pin and track generated-code migration separately; this is not
a release-blocking correctness failure for the declared beta language mode.

### P3 - Accepted: local consumer and dependency notices

Flutter reports newer incompatible versions for five pinned packages. Android
reports a Kotlin plugin migration notice and an SDK XML version warning. The
unsigned iOS consumer reports the future UIScene migration notice. These are
non-fatal toolchain notices; exact pins, package metadata, tests, and both
consumer builds pass. Disposition: preserve the reviewed pins and address
upgrades through normal dependency work, not this integration.
