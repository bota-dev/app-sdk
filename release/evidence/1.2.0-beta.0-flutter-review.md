# Flutter 1.2.0-beta.0 Integration Review

## Verdict

The initial whole-branch review found two P2 issues. The single final-review
fix wave is implemented locally and awaits one scoped re-review. Release remains
BLOCKED as `1.2.0-beta.0`; no replacement version was selected. No branch was
pushed and no workflow or publication was triggered by this Flutter branch or
either fix round. Separately, an external beta.0 tag and release run exist on

## Findings

### P2 - Fixed, pending scoped re-review: adapter errors lost stable identity

Commit `8f73c8e1661dc5c8f0c093a9c2a97ba2cee7e7cb` adds an exhaustive
sanitized projection for every adapter-only outer bridge code. It preserves the
operation supplied by the public Dart call, maps ownership rejection to the new
stable `operationNotOwned` code, and leaves typed native `BotaSDKError` mapping
unchanged. Cross-boundary tests cover configuration conflict, operation
ownership, device lookup, and engine detach. Malformed and unknown errors fail
closed as `internal`, and native message/detail text is not exposed as a public
branching surface.

### P2 - Fixed, pending scoped re-review: beta.0 remained operator-actionable

Commit `280aab6be16eae317ff2576fdb6719cbf8529909` makes the Flutter
candidate script derive a future example from the synchronized SDK version but
reject occupied `1.2.0-beta.0` before generating a candidate. It removes the
release workflow's beta.0 interactive-publish summary and updates primary
operator/package docs to require an explicit synchronized-version decision.
No replacement version was inferred or written.

### P3 - Fixed, pending scoped re-review: generated Kotlin whitespace

Commit `d921c1f21e6647d70ee5b9bb6d5b431d215fcdc0` normalizes Kotlin in the
Pigeon generation path, regenerates the committed bridge, and adds a regression
over every checked-in generated output. `git diff --check 1579e4d...d921c1f`
passes.

### P3 - Accepted: replay tombstone lifetime

The final fix wave does not add a risky lifecycle epoch or eviction policy.
Request and operation IDs are random 128-bit values, retained state is released
with the owning engine/client, and this remains an explicit first-beta residual
to measure before long-lived high-frequency workloads are declared ready.

### P1 - Resolved: stale policy removed authoritative automatic verification

The first Task 9 conflict resolution followed stale prompt text and removed
the `pull_request` and main-branch `push` triggers already present on
`origin/main`. Commit `1579e4d3...` makes the authoritative policy explicit:
CI and the license gate run on pull requests and main pushes, while CI
concurrency cancels only superseded pull-request runs and preserves every main
candidate. The parsed-YAML regression now requires all three triggers, the
exact main branch filter, and the exact CI concurrency expressions.

### Release blocker - Open: beta.0 is occupied by non-Flutter source

Annotated tag `v1.2.0-beta.0` points to
`1579e4d3be1c0b31255a94ab7c62df11d6e0c01d`. The tagged tree contains no
Flutter package and its release example lists only Apple, Android, React Native,
and Web. GitHub Actions release run `35146481944` was observed in progress for
that exact source at `2026-09-16T21:02:08Z`.

This local Flutter candidate has different source and cannot become the
synchronized beta.0 without moving or replacing an existing release identity,
which is prohibited. No remote action was taken. Release remains blocked until
the owner makes an explicit new synchronized version decision.

### P2 - Resolved: Flutter conformance overstated the integrated workflow set

The first post-merge package run discovered 33 canonical traces and failed five
tests because the pre-integration Flutter test assumed every canonical command
was in the Flutter beta. The four newly integrated Encrypted Upload v2 traces
belong to native and React Native in this release. The contract now discovers
all 33, asserts the explicit four-trace unsupported set at
`frameworks/flutter/bota_flutter_sdk/test/workflow_conformance_test.dart:196`,
and replays all 29 supported traces through the typed Dart facade.

### P3 - Accepted: Flutter Apple bridge has Swift 6 sendability warnings

`tools/flutter/test-apple-adapter.sh` passes all 35 tests but Pigeon 28 output
and `BotaAppleAdapter.swift` emit sendability warnings under the installed
Swift 6 compiler. The supported plugin contract intentionally compiles this
generated bridge in Swift 5 language mode. The separately shipped native Apple
SDK passes strict concurrency with warnings as errors. Disposition: retain the
reviewed Pigeon pin and track generated-code migration separately; this is not
a release-blocking correctness failure for the declared beta language mode.

### P3 - Accepted: local consumer and dependency notices

Flutter reports newer incompatible versions for five pinned packages. Android
reports a Kotlin plugin migration notice and an SDK XML version warning. The
unsigned iOS consumer reports the future UIScene migration notice. These are
non-fatal toolchain notices; exact pins, package metadata, tests, and both
consumer builds pass. Disposition: preserve the reviewed pins and address
upgrades through normal dependency work, not this integration.

- The nine Apple physical-device tests were skipped under their supervised
  opt-in gate. No physical-device claim is made.
- No Android emulator, signed iOS archive, or device interoperability run was
  performed as part of this local integration.
- External beta.0 tag/release state belongs to `1579e4d3...`, which does not
  contain Flutter. Public artifacts from that run, if or when produced, cannot
  verify this different local source.
- No CI/CD run was triggered by this Flutter branch or this fix. Workflow
  conclusions are based on parsed contract tests and local execution of the
  same build and package commands.
- The candidate source revision predates this evidence-only documentation
  commit to avoid a self-referential archive hash. A new synchronized version
  decision is required before exact-tag tooling can rebuild and compare a
  releasable Flutter candidate.
