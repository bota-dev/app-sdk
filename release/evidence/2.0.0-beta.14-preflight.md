## Required sequence

1. Review/commit source, prepare synchronized metadata on the task branch, and
   run the temporary hosted preparation workflow. Its isolated local commit only
   gives Flutter's clean-source gate the generated identity/Apple files.
2. Verify the exact run SHA/success and artifact digest before reviewing/applying
   its allowlisted generated patch. Remove the temporary workflow. Record actual
   checks here; no successful check is inferred from metadata preparation.
3. Require CI and License Gate on the final branch revision before ordinary main
   integration. Then require the exact main-push checks and complete inventory.
4. Recheck version slots, create a new annotated tag bound to that source/run/raw
   inventory digest, and use the existing protected approval after promotion.
5. Verify public native/npm/Flutter payloads and consumers; advance only npm beta.
   Publish completion evidence separately from consuming native app/hardware tests.

Do not reuse beta.13 bytes for the fix, move an existing tag, relax error/identity
gates, claim legacy uploaded alone proves integrity, or claim Apple physical
qualification from hosted lifecycle tests. Native applications need a new binary.
