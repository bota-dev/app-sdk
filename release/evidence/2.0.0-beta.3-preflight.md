# App SDK 2.0.0-beta.3 Preflight

Prepared 2026-09-26 following the owner's request to publish after the Android
encrypted Bluetooth upload test. Publication is not yet claimed. Beta.2 is
already occupied; all historical releases and npm latest tags remain unchanged.

## Scope

- Maintenance behavior reference `318974f925a573cf04b0d624978bee04784af09b`;
  frozen public API baseline remains 0.0.65. See `docs/parity/` for limits.
- Native mixed recording catalogs, scoped opaque upload context and cancellation,
  with an explicit React Native encrypted-upload-v2 entry point.
- Normalize advertised MAC addresses, preserve Android BLE UUID identity, refresh
  firmware/MTU after connection, and correct catalog characteristic UUIDs.
- Retain bounded legacy transfer bursts and write final ACK/NACK to control 0404.
- Fix unpublished CocoaPods CI evidence without weakening tagged checksum gates.
- Synchronize Apple, Android, React Native, Web and Flutter versions. No app,
  backend or firmware deployment is part of this release.

## Supervised Android Evidence

SDK behavior revision `3b5eb938b756b5409b0f5f139cabfdb2799de573` was tested with
firmware 1.0.18 on a Bota Pin and a Samsung SM-A166U1. Demo's local native upload
module also required a separate Android JSON slash-escaping identity fix; it
is not shipped inside this SDK. Tested APK SHA-256:
`d3fbf6619149a1f0ace4c3d0a7e88e8c9c58ad58c351fb8c836b7012beaae991`.

The application selected the explicit v2 BLE session, with device cellular off
and WiFi unconfigured. One pending recording became zero after receipt-gated
completion. The cloud recording was marked Bluetooth, had a nine-second
duration, and playback advanced to two seconds without a player error. The
device remained connected and idle. Phone internet carried staging bytes to S3;
device direct WiFi/cellular upload was not the path.

Keep `encryptedUploadV2` contract-only metadata and runtime/firmware flags false.
The owner-authorized beta release does not imply complete hardware qualification,
Flutter/Web v2 support, audible quality analysis, or sustained recording-control
acceptance. App consumption needs matching native binaries and the application
upload integration; a JavaScript-only update is insufficient.
