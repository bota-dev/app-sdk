# React Native 1.1.0 Release Evidence

## Status

Published. Protected workflow run `33685720066` verified the exact npm artifact,
and Demo and Bota One consume it from their registry lockfiles. Release-mode
native builds succeeded for both consumers after setting their Expo-generated
Android minimum SDK to API 26.

On 2026-09-02, the npm channels were reclassified without republishing either
artifact: the maintained legacy line is `latest` at `0.0.65`, while the
synchronized App SDK line is `beta` at `1.1.0`. The GitHub `v1.1.0` release is
also marked as a prerelease.

## Local Consumers

The packed npm artifact, installed without a source link, produced successful
release-mode Expo bundles for both iOS and Android in Demo and Bota One. The
applications retain unrelated pre-existing TypeScript diagnostics; acceptance
found no missing SDK export or unresolved compatibility method.

Demo preview and production EAS builds, submissions, and OTA workflows
completed successfully. Bota One production and both OTA workflows completed
successfully, and its preview iOS and Android build jobs succeeded. The Bota
One preview workflow remains failed only at the separate Play internal-track
submission because Google Play requires the preview application's first
release to be uploaded manually before API submissions can create subsequent
releases.

## Publication Controls

The protected release workflow:

1. Verifies the package, Codegen contract, exact frozen API, tests, and license
   policy.
2. Packs with npm `12.0.2` and uploads the tarball as immutable release input.
3. Includes the tarball in the annotated tag candidate inventory.
4. Exercises Apple OTA and recording progress callbacks with synchronous,
   lock-protected captures so release acceptance does not depend on unstructured
   task scheduling.
4. Publishes through npm OIDC trusted publishing without a write token.
5. Compares npm `dist.shasum` with the candidate before and after publication,
   making a rerun safe after an uncertain outcome.

The npm package trusted publisher must be configured as:

- Organization: `bota-dev`
- Repository: `app-sdk`
- Workflow: `release.yml`
- Environment: `release`
- Allowed action: `npm publish`
