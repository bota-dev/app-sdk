# Synchronized beta.17 preparation

The Demo/Bota One generated-JS integration exposed a managed encrypted-v2 proxy
admission bug: a valid HTTPS customer proxy with routes at its origin root was
rejected. Beta.17 preparation corrects the Rust routing validator and RN facade,
and makes existing pure application helpers available through `/runtime`.
Beta.16 source, tag and published archives remain immutable.

## Design review and acceptance

| Accept genuine root/prefixed HTTPS proxies without routing tricks | RN normalization forwards exact origin/prefix; all 15 managed JS backend tests pass with generated source, including exact root/prefixed HTTP URLs | matched in controlled tests |

The scoped preparation branch/workflow produces canonical ordinary JS on
`x86_64-unknown-linux-gnu`, Rust 1.98.0, then Apple pins and the complete Flutter
archive inventory. The temporary workflow is removed before final CI. No tag or
registry publication occurs in preparation. Exact branch/main CI and License,
the complete annotation-bound candidate inventory and normal protected release
approval remain required before publication.

The [Android 15 AtomicFile source](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/core/java/android/util/AtomicFile.java)

admission is implied. Local full xtask compilation is unavailable because the
cached Windows GNU compiler lacks `dlltool.exe`; no additional toolchain was
downloaded. The exact hosted Rust/tooling gate remains required.

Existing native queues/files/checkpoints are not automatically imported by
`runtime.createUploadRecoveryProvider`. That method binds generated recovery
policy; it does not migrate old storage. Applications must retain and explicitly
refuse unresolved old evidence until a reviewed scoped migration or drain
completes. Fresh generated-runtime restart recovery is a separate acceptance
case from migration of legacy native pending work.
