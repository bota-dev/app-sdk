# Synchronized beta.17 preparation

The Demo/Bota One generated-JS integration exposed a managed encrypted-v2 proxy
admission bug: a valid HTTPS customer proxy with routes at its origin root was
rejected. Beta.17 preparation corrects the Rust routing validator and RN facade,
and makes existing pure application helpers available through `/runtime`.
Beta.16 source, tag and published archives remain immutable.

## Design review and acceptance

| Requirement | Implementation/evidence | Status |
| --- | --- | --- |
| Shared route behavior remains Rust-sourced | `ManagedUploadInput` accepts an explicit empty prefix, produces exact root paths, defaults omitted prefix to `/v1`; all 13 managed-upload Rust tests pass after the new route regression failed on beta.16 | matched in native tests; canonical artifact pending |
| Accept genuine root/prefixed HTTPS proxies without routing tricks | RN `baseUrl` normalization forwards exact origin and canonical prefix | red regression reproduced; corrected facade/generated checks pending |
| Keep origin/scope/auth/receipt fences | Only the empty-prefix admission predicates change in Rust and compatibility Apple/Android; native route fixtures cover the same root/prefixed/rejected routes | Rust tests pass; native host regressions pending |
| Native-free `/runtime` application helpers | Pure sync status, presence and upload recovery version exports; generated runtime recovery provider retains Rust policy | red import regression reproduced; corrected checks pending |
| Preserve original identity and synchronized release policy | Original npm name, all five candidate versions beta.17; private companion unchanged | metadata preparation |
| Deliver to installed production apps | Host OS ports, Metro/Android build, device/backend uploads and recovery | unverified; application work owns acceptance |

The scoped preparation branch/workflow produces canonical ordinary JS on
`x86_64-unknown-linux-gnu`, Rust 1.98.0, then Apple pins and the complete Flutter
archive inventory. The temporary workflow is removed before final CI. No tag or
registry publication occurs in preparation. Exact branch/main CI and License,
the complete annotation-bound candidate inventory and normal protected release
approval remain required before publication.
