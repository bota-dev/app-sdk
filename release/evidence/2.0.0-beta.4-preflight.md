This candidate integrates Web actions and passive client presence with main
`dd8c6e5`, retaining the native maintenance/recovery work. The reviewed source

The existing beta.3 tag and pending release are not changed or reused.

## Scope and design review

See [Web integration](../../docs/testing/web-actions-integration.md) for the
requirement-by-requirement comparison. Web uses the canonical Rust upload-context
codec; no firmware wire changes or new provisioning protocol are introduced.
The Portal owns HTTP authorization and scoped recovery. SDK callbacks retain
exclusive connection ownership until workflow handoff; signed successor identity
is checked before retained ciphertext progress is replaced. Signature authority
and receipt-before-delete remain device/backend responsibilities.

Apple cancellation and detach checks cover delayed connection-identity lookup.
Client presence contains SDK identity and session-scoped metadata, not a permanent
phone identity. Flutter v2 runtime remains unavailable, and compatibility flags
are not promoted on the strength of host tests.
