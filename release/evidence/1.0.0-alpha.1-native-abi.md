# Native ABI Foundation Evidence: 1.0.0-alpha.1

Date: 2026-08-30
Status: ABI v1 foundation verified; no native facade artifact published.

## Scope

This evidence freezes the typed native boundary consumed by future Apple and
Android facades. It covers the opaque engine lifecycle, command dispatch,
correlated host events, ordered effects and notifications, shared protocol
codecs, structured errors, explicit ownership, and standalone C and Swift
callers linked to the shipping FFI crate.

It does not claim an Apple SDK, Android SDK, XCFramework, AAR, native Bluetooth
transport, application migration, or physical-device acceptance. Published
Apple and Android facade capabilities are empty for this milestone.

## Frozen ABI Surface

- 10 workflow command kinds
- 34 correlated host-event kinds
- 30 ordered host-effect kinds
- 12 workflow-notification kinds
- 10 shared protocol decoder kinds
- 13 shared protocol encoder kinds
- 9 explicit host capability bits
- 5 field representations: unsigned, signed, Boolean, UTF-8, and raw bytes

All exported symbols use the `bota_device_sdk_v1_` prefix. Inputs are borrowed
only for the duration of a call. Engine handles remain caller-owned until one
`engine_free`. Returned packet and error owners remain SDK-owned until exactly
one matching free; views and slices borrowed from an owner become invalid when
that owner is freed. Output pointers must be writable and empty. Violating
foreign pointer, lifetime, or single-free rules is undefined behavior.

No JSON or base64 crosses the shipping ABI. Binary protocol payloads and opaque
checkpoints use raw byte slices. Packet meanings are extensible typed field
lists, and existing numeric kind, field, operation, capability, and error values
cannot change within ABI v1.

## Next Gate

The Apple facade must consume this header without redesigning ABI v1, build
device and simulator XCFramework slices, pass Swift package import tests and
fake-host workflow conformance, and then pass the physical-device matrix. Until
those gates are recorded separately, the existing native Apple repository and
React Native SDK remain authoritative for production use.
