## Design review

The [preflight](2.0.0-beta.16-preflight.md) retains the preparation snapshot.
The [runtime contract](../../docs/parity/react-native-runtime.md) maps shared
Rust behavior to generated JS and narrow version 1 installed OS ports, following
App SDK Architecture sections 5.5 and 6.3 and the owner's original-package
decision. Publication and acceptance are tracked independently below.

| Requirement | Evidence | Status / remaining verification |
| --- | --- | --- |
| Retain the original RN package identity | Actual public `@bota.dev/react-native-app-sdk@2.0.0-beta.16` exposes `/runtime`; companion is private | Matched in public archive and fresh consumer |
| Execute shared Rust behavior as ordinary JS | Canonical generation, 106 matching inputs, Rust/JS differential checks, pinned Hermes and fresh public runtime execution | Matched source/compiler/public consumer gates; installed-app qualification unverified |
| Preserve native compatibility | Frozen public exports, native files, Codegen and full native main-CI gates retained | Matched source/native CI; app binary delivery separate |
| Preserve scope, durability and cryptographic authority | Rust workflow/receiver tests; bounded SDK-internal ciphertext and signed documents; device/backend retain trust verification and recording decryption | Matched source gates; installed durability and broad physical recovery remain unverified |
| Publish exact approved bytes through existing protection | Annotation-bound main inventory, protected publisher, occupied-version retry, public CocoaPods metadata, Central state and preserved Flutter candidate | Matched across all five publications |
| Verify public consumers and package channels | Fresh generated JS/declarations, SwiftPM, clean CocoaPods, API 26/35 and complete Flutter public file verification pass; independent npm bytes/tags match | Matched public package gates; installed-app/device acceptance separate |
| Deliver compatible logic through app OTA | Published generated JS uses existing version 1 OS ports; new OS capabilities still require an app build | Source/package capability matched; app OTA delivery and physical acceptance unverified |

Tagged packaged documents, including all 59 Flutter package files, retain their
original preparation snapshot. This nonpackaged publication record supplies
later evidence without moving the tag or replacing accepted artifacts.
